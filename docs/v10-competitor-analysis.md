### 1.3 V10 独特优势

1. **最小** — 1.93M 参数，7.3MB，唯一能装进手表 Flash 的中文嵌入模型
2. **最快** — 0.33ms/inference，比竞品快 10-30 倍
3. **纯 C** — 不依赖 PyTorch/ONNX，libc + libm 即可运行
4. **零依赖** — 无需安装任何运行时，直接链接
5. **已集成** — openvela 上已跑通端到端（QEMU 验证通过）

### 1.4 V10 劣势

1. MTEB 分数未知（未上排行榜），质量差距不明
2. 96 字上下文限制，竞品可处理更长文本
3. 自定义 tokenizer（ord%4096），非标准，微调困难
4. 仅支持中文，竞品多语言
5. 20 类 recall@3 仅 47%，竞品可能更好

## 二、性能优化方案（拉满性能，不缩小模型）

> V10 的 1.93M 参数 / 7.3MB 够用，瓶颈是训练数据质量，不是模型大小。

### 2.1 训练数据优化（根因解决，最高优先级）

| 方案 | 预期收益 | 难度 |
|------|---------|------|
| Hard negative mining | 易混淆类别拉开距离 | 中 |
| 类别标签 + Supervised Contrastive | 针对性训练 | 中 |
| 扩大 vocab 到 10k | 消除 token clip 信息丢失 | 低 |
| 增加混淆类别训练样本 | 装修↔家居、健身↔运动 | 中 |

### 2.2 量化压缩（不改模型结构）

| 方案 | 大小缩减 | 精度损失 | 难度 |
|------|---------|---------|------|
| FP32 → FP16 | 50% (7.3→3.6MB) | <1% | 低 |
| FP32 → INT8 | 75% (7.3→1.8MB) | 2-5% | 中 |

### 2.3 推理优化（不改模型）

| 方案 | 效果 | 难度 |
|------|------|------|
| ARM NEON SIMD | 2-4x 加速 | 中 |
| 批量推理 | 多条一起算 | 低 |
| 预计算 embedding | 常用文本离线算好 | 低 |

### 2.4 检索优化（不改模型）

| 方案 | 效果 | 难度 |
|------|------|------|
| Top-3 展示 | 缓解单条误排 | 低 |
| 置信阈值 | <0.3 不显示 | 低 |
| 查询扩展 | 短查询自动补同义词 | 中 |

## 三、推荐优先级

| 优先级 | 方案 | 预期收益 | 工作量 |
|--------|------|---------|--------|
| 1 | Top-3 + 置信阈值 | 立即改善体验 | 1小时 |
| 2 | Hard negative 微调 | 拉开混淆类别 | 1天 |
| 3 | 扩大 vocab 到 10k | 消除 token clip | 2小时 |
| 4 | FP16 量化 | 大小减半 | 2小时 |
| 5 | ARM NEON 加速 | 速度翻倍 | 1天 |

## 四、比赛策略

**核心卖点：唯一能跑在手表上的中文嵌入模型**

- 竞品都太大（80MB+）或需要 PyTorch
- V10 的 7.3MB + 0.33ms + 纯C 是独一无二的组合
- 评审看的是"作品本身 + README + 日志"，技术方案的创新性比 MTEB 分数更重要

**答辩要点：**
1. 为什么不用 bge/small？因为手表 Flash 只有 20MB，bge 要 95MB
2. 为什么不用 ONNX Runtime？因为 MCU 上没有运行时
3. 质量够用吗？recall@3=100%（200条），日常场景完全够用
